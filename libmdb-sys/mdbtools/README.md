# Vendored mdbtools

Source of [mdbtools](https://github.com/mdbtools/mdbtools) v1.0.1, used by the
`bundled` feature of `libmdb-sys`.

- Origin: https://github.com/mdbtools/mdbtools/releases/download/v1.0.1/mdbtools-1.0.1.tar.gz
- SHA-256: `ff9c425a88bc20bf9318a332eec50b17e77896eef65a0e69415ccb4e396d1812`
- License: LGPL-2.0-or-later (see `COPYING.LIB`)

Only `include/`, `src/libmdb/` and `src/sql/` are kept. Build system files and
`include/mdbtools.h` (generated by `build.rs` instead) are removed. The build
uses the fake GLib shim (`fakeglib.c`, `mdbfakeglib.h`) instead of GLib. The
generated SQL parser and lexer (`parser.c`, `parser.h`, `lexer.c`) come from
the release tarball as is.

## Updating

1. Extract a new release tarball and repeat the steps above.
2. Regenerate the pre-generated bindings from the repository root (needs
   libclang):

   ```sh
   # 64-bit Unix (run on any 64-bit Unix host)
   libmdb-sys/regenerate-bindings.sh

   # Windows, with MinGW headers
   BINDGEN_EXTRA_CLANG_ARGS="--sysroot=$MINGW -I$MINGW/include" \
       libmdb-sys/regenerate-bindings.sh x86_64-pc-windows-gnu
   ```

   `$MINGW` is the `x86_64-w64-mingw32` directory of the MinGW toolchain.
   The numbers in `_bindgen_ty_N` names can differ between hosts. This is
   harmless: bindgen's layout assertions check the structs at compile time.
